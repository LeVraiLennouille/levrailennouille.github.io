Brief : Migrer le site du CMS Odoo vers un code sur-mesure (HTML/CSS/JS), compatible avec l'écosystème existant du client.

Objectif : Gagner en liberté de mise en page et améliorer la conversion.

Livrables : Charte graphique, logo redessiné, design system et UI Kit, maquettes UI/UX prêtes pour le développement.

Point de départ : un site sous Odoo

Le site d'YLIGEN tournait sur le CMS Odoo. Le back-office fonctionnait, mais les templates limitaient la mise en page et l'identité visuelle restait générique. La mission : migrer vers un code sur-mesure (HTML/CSS/JS), compatible avec l'écosystème du client, et refondre l'interface UI/UX.

Audit : limites du CMS et points à conserver

J'ai listé ce que les templates Odoo empêchaient de faire, puis ce qui pouvait rester dans l'arborescence. Les wireframes exploitent la liberté du code sur les zones qui pèsent sur la conversion : hero, formulaire de contact, footer. Chaque maquette a été pensée pour être réalisable en intégration front-end.

Avant / Après — Logo

Nouvelle charte et design system

J'ai créé une charte graphique, un design system et un UI Kit sur mesure, avec une palette et une typographie modernisées. Le logo a été redessiné avec un tracé plus fin, pour s'intégrer à la nouvelle interface (comparaison ci-dessus).

Ce qui change dans l'interface

Trois zones ont été refaites : hero et navbar, formulaire de contact, footer (comparaisons ci-dessous). Poids de page après migration : 2 Mo, contre 5 Mo sous Odoo.

Ce que j'en retiens

Concevoir autour d'Odoo suppose de connaître les limites du back-office du client. Une maquette que le client ne peut pas maintenir n'a pas de valeur : la maintenabilité est devenue un critère de validation de chaque écran.
